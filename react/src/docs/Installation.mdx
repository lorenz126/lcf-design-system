# Installation

<Subtitle>React 18 or 19. Tailwind is optional.</Subtitle>

<Steps>
<Step title="Install">

```bash
pnpm add "github:lorenz126/lcf-design-system#v0.4.0&path:/react"
```

A release tag carries the built package, so installing runs nothing —
no build step, nothing to allow in `allowBuilds` (pnpm 12) or
`onlyBuiltDependencies` (pnpm 10). Upgrade by changing the tag, after
reading *Breaking* in the package's `CHANGELOG.md`.

**pnpm** — `&path:/react` installs a subdirectory of the repository,
and npm has no syntax for that.

**Pinned to a commit instead of a tag**, the package arrives as source
and builds itself on install, which pnpm allows only when the app says
so in `pnpm-workspace.yaml`. pnpm 12 wants the dependency's full
resolved spec as the key — the bare name is not enough, measured — and
prints it when it refuses:

```yaml
allowBuilds:
  "@lcf/design@https://codeload.github.com/lorenz126/lcf-design-system/tar.gz/<commit>#path:/react": true
```

The key names the commit, so it changes with every new pin — one more
reason to pin a tag. pnpm 10 takes the name: `onlyBuiltDependencies:
["@lcf/design"]`.

</Step>
<Step title="Styles, once, first">

```ts
// main.tsx — before anything that renders a component
import '@lcf/design/css'
```

Everything sits in `@layer lcf`, so the app's own CSS wins without a
specificity fight.

With Tailwind 4, the tokens are available as utilities too
(`bg-surface-raised`, `text-secondary`, `text-danger`, `heading-md`):

```css
@import "tailwindcss";
@import "@lcf/design/css";
@import "@lcf/design/tailwind";
```

</Step>
<Step title="Theme before first paint">

```html
<!-- index.html, in <head> -->
<script>/* paste themeScript from @lcf/design/theme */</script>
```

Or in a React SSR head:

```tsx
<script dangerouslySetInnerHTML={{ __html: themeScript }} />
```

It reads `localStorage.theme` and falls back to the OS. The same script
works for a static build with no server: it runs in `<head>` before the
body exists, whatever produced the HTML.

</Step>
<Step title="The provider">

```tsx
import { LcfProvider } from '@lcf/design/components/LcfProvider'
import { Link } from 'react-router'

<LcfProvider locale="de-CH" linkComponent={Link}>
  <App />
</LcfProvider>
```

</Step>
<Step title="Import components by path">

```tsx
import { Button } from '@lcf/design/components/Button'
import { Badge } from '@lcf/design/components/Badge'
```

One path per component, so a page that uses a button pulls a button.

</Step>
</Steps>

## Your own colour

An app sets three tokens and nothing else:

```css
/* src/theme.css, after @lcf/design/css */
:root, [data-theme="light"] {
  --accent: #e4002b;        /* rings, borders, marks — 3:1 */
  --accent-text: #c00024;   /* the colour as text — 4.5:1 */
  --accent-solid-bg: #d10028;  /* ground for white text — 4.5:1 */
}
[data-theme="dark"] {
  --accent: #ff4d6a;
  --accent-text: #ff6b83;
}
```

Then check them, in the app's CI:

```bash
npx lcf-check-contrast src/theme.css
```

Every `primary` in every component follows, and the check measures all
of it against the app's values.
