# Colors

<Subtitle>Three tiers, and components may read only the last two.</Subtitle>

1. **Primitives** — a neutral ramp and six hues, each with a separate
   light and dark value and a darker `-text` variant graded for AA.
2. **Roles** — `--fg`, `--fg-muted`, `--fg-subtle`, `--bg`,
   `--bg-raised`, `--bg-sunken`, `--fill-quiet`, `--fill`,
   `--fill-strong`, `--border`, `--border-strong`, `--accent`,
   `--accent-text`, `--accent-solid-bg`.
3. **Intents** — what a component is told. Eight colours, six roles
   each.

`warning` and `caution` are held to 3:1 by decision: at AA-legible
lightness, orange and yellow turn brown. Fine for a two-word status;
not for a sentence.

## Giving statuses a fixed meaning

A status picks a meaning, and the meaning picks the hue. Write the map
once in the app:

```ts
const OFFER: Record<OfferStatus, Color> = {
  draft: 'secondary', approved: 'primary', sent: 'info', won: 'success', lost: 'danger'
}
const LICENCE: Record<Licence, Color> = {
  free: 'success', attribution: 'info', internal: 'secondary', unresolved: 'caution'
}
```

Then the colour of "lost" is the same in the list, the board and the
report, because none of them chose a hue.

## Measured, not assumed

`pnpm test:contrast` resolves every pair in both themes from the CSS
itself — 322 pairs — and fails on any below its floor. Every relaxed
pair carries its reason in the output.
